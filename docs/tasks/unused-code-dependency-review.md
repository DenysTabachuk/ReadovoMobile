`hovered` is declared by **Expo's own** `types/react-native-web.d.ts`, not by the
installed react-native-web package. The chain in this checkout is:

```text
frontend/tsconfig.json includes expo-env.d.ts
  -> reference types="expo/types"
  -> expo/types/index.d.ts references ./react-native-web
  -> declare module 'react-native'
  -> interface PressableStateCallbackType { readonly hovered: boolean }
```

React Native's native Pressable.d.ts only declares `pressed`. Full tsc loads all
configured roots, including the generated Expo ambient reference. A ts-jest
compilation of an isolated test/import graph can omit that reference. Runtime
jest.mock calls do not change TypeScript's declarations. The compiler API check
against questionOptions/index.spec.ts reproduced both shapes using the same
tsconfig compiler options and different roots. Its named pressableState object
fits both structural types; an inline object containing hovered can trigger an
excess-property error in the native-only graph, while omitting it fails under the
augmented graph. Removing react-native-web would not remove Expo's augmentation.
